# OCR document automation — портфолио-демо

**Самостоятельный пример обработки документов: PDF → OCR полей → подтверждение оператором → ready/problems → локальный план RPA.**

Проект позволяет изучить основные этапы распознавания и подготовки документов без доступа к рабочему порталу. Он создан по мотивам OCR Studio v43.17.49 и предназначен для демонстрации подхода к автоматизации документов.

## Что я сделал

- Реализовал преобразование первой страницы PDF в изображение и распознавание Tesseract в двух вариантах подготовки изображения.
- Разделил извлечение ФИО и номера помещения; для номера учёл контекст строки таблицы.
- Добавил подтверждение и исправление полей оператором перед сохранением результата.
- Организовал ready/problems: исходный файл сохраняется, подтверждённая копия получает имя «ФИО (номер).pdf», совпадающие имена — суффикс.
- Добавил mock-robot для формирования локального JSON-плана и тесты извлечения полей и безопасного сохранения.

## Результат и границы

Результат обработки — подтверждённая копия PDF в ready/ либо копия неподтверждённого документа в problems/. Команда mock-robot создаёт локальный план действий: сетевых запросов и входа в портал нет.

Основное приложение с Tkinter, библиотекой шаблонов, обработкой партий и Selenium опубликовано отдельно: [OCR Studio](https://github.com/alexandrela191-hub/OCR-Studio), [релиз v43.17.73](https://github.com/alexandrela191-hub/OCR-Studio/releases/tag/v43.17.73). Возможности и точность двух реализаций нельзя считать одинаковыми.

## Что демонстрирует проект

1. Первая страница PDF преобразуется в изображение (Poppler, 300 DPI).
2. Tesseract распознаёт текст на исходном изображении и варианте с автоконтрастом; выбирается результат с большей средней уверенностью.
3. Кандидаты на ФИО и номер помещения извлекаются отдельно. Для номера учитывается строка таблицы «Вид помещения | Номер помещения | Площадь | Доля».
4. Оператор проверяет оба поля и подтверждает их. Неподтверждённые документы попадают в `problems/` как копии, исходный файл сохраняется.
5. Подтверждённая копия записывается в `ready/` как `ФИО (номер).pdf`. Совпадающие имена получают суффикс, существующие файлы не перезаписываются.
6. Команда `mock-robot` формирует локальный JSON-план действий; сетевых запросов и входа в портал нет.

## Запуск (Windows)

Установите Python 3.10+, Tesseract OCR с русским языком и Poppler; добавьте `tesseract.exe` и `pdftoppm.exe` в `PATH`.

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m ocr_showcase process C:\путь\к\сканам
python -m ocr_showcase mock-robot ready
python -m unittest discover -s tests -v
```

При обработке программа показывает предложения OCR и ждёт подтверждения или исправления. Перед запуском на собственных документах убедитесь, что права на их обработку у вас есть. `ready/`, `problems/`, `source/`, PDF, JSON и изображения игнорируются Git.
